## Efficiency and resilience

- Weather files are parsed once and indexed by date in a cancellable worker, with a 25 MB input budget and 600,000-record limit. The worker receives only the analysis settings it needs.
- The UI memoizes its analysis identity, reuses it for result/resume checks and receives worker progress at most every 100 ms. Nonphysical metadata such as address, elevation and rated power is excluded from numerical identity. Full scientific inputs remain represented; no collision-prone short hash was introduced.
- Period solves reuse one backend/device and current geometry. A bounded pose geometry LRU retains up to eight poses/32 MiB of counted geometry buffers, allowing one current geometry larger than that budget. Backend-owned acceleration data and the live geometry are additional memory.
- Diffuse visibility is integrated in tiles of at most 2 MiB, including transmitting-module counts. The old 92.2 MB full count matrix is no longer materialized at 20,000 receivers × 2,305 patches. Within-cell samples remain sequential. Direct rays use small per-step arrays.
- Visibility cache uses byte-aware LRU eviction: memory 32 MiB/1,024 entries; IndexedDB 128 MiB/2,048 entries. Warm poses survive normal churn, cache failures remain nonfatal, and development diagnostics expose cache use.
- Crop summaries visit intersecting grid cells and cache statistics by result and bed geometry. Exact overlap weighting and weighted quantiles are retained; summed-area approximations were unnecessary for the bounded overlap implementation.
- Repeated hardware shares geometry and is instanced in large interactive scenes. Fine cell-line decoration is limited to small scenes. Scientific occluders remain separate and complete. A 48,000-module fixture collapses 49,440 hardware meshes to three instanced drawing objects; this is not a frame-rate claim.
- Browser preference saves are debounced. Large retained weather is stored in IndexedDB, with a small localStorage pointer committed only after the snapshot; bounded snapshot pruning retains recent data. Inline fallback and visible storage failures preserve the export route. Sensor/crop layouts remain explicit-export only, now with an unsaved-layout indicator and navigation warning.
- Publication packages share texture-free geometry/hulls across figures and reports; crop statistics are reused. Optional report/CSV/PNG code loads on demand. Main production chunk: **492.83 kB / 157.18 kB gzip**, down from 513.62/161.76 kB; the previous main-chunk warning is gone. Cold-start latency was not measured, so no user-visible startup speed claim is made.
- CSV formula escaping now includes negative and whitespace-prefixed text while preserving numeric negative coordinates. WebGL context loss shows an SVG fallback; context restoration reuses the drawing/camera.
- Explicit numerical revision `solar-noaa-perez-gap-v2` enters results, provenance, analysis and visibility identities. Older numerical results need recalculation; study geometry and field layouts remain importable. This is deliberate cache/result invalidation, not a schema reset.

The [controlled local microbenchmark](review-fixes-performance.json) compares the original parser and crop-summary functions from `e549b7a` with the new functions on identical fixtures and current shared helpers. On this single M2 Pro / Node 23.11 run, annual CSV parsing fell from **2,105 ms to 29.7 ms**; 200 crop summaries over a 20,000-cell grid fell from **161 ms to 1.51 ms** (0.13 ms warm). These are microbenchmarks, not whole-application or cross-device guarantees. The same record includes small 366-day CPU fixed/tracking cold/warm runs. Actual browser transmitting checks show GPU benefits for the tiled fixture and trackers but overhead on tiny fixed cases; automatic selection remains GPU-preferred under the project's contract. A universal backend size cutoff is not justified by these fixtures.

- Installed Radiance: **51,100 rays / 10 cases**, zero first-hit mismatches. Scalar transmission: **32 rays / 8 combinations**, maximum difference **1.11 × 10⁻¹⁶**.
- Actual Chromium 153 / WebGPU: all five opaque and transmitting rack types agree exactly with CPU in Wh, DLI and sunlight; warm reuse, real device loss, allocation failure and storage failure remain correct. An additional **646-receiver / 2,305-patch transmitting fixture** crosses the tile boundary with zero CPU/GPU differences. A four-receiver leap-year browser run completes all 366 days/12 months and validates its saved result.
- Actual Chromium CPU/export/storage smoke: 80 receivers, zero measured DLI, successful SVG/PNG/report/ZIP, result retained, and IndexedDB weather round trip. Actual WebGL context-loss/restoration fallback passes.
- [Independent physics record](independent-physics-validation.json): pvlib 0.13.0 NREL SPA across 288 hourly positions, four sites, three dates and fractional UTC offsets; maximum angular sun difference **0.5671°**. Tracker equations agree to **1.85 × 10⁻¹³°** using the same input sun. Radiance `gendaylit` independently supplies Perez distributions: **11 of 12** requested sky cases compared; the 5°/DNI 800/DHI 100 case produced Radiance's error sky and is explicitly unvalidated. Maximum normalized sky L1 difference is **0.01650**. Six finite-array daily cases across both hemispheres and fixed/single/dual trackers differ by at most **0.6455 Wh/m²** and **0.01554 percentage points** in receiver sunlight. PAR partition and source timing remain shared in that comparison; it is not independent biological/PAR calibration. See the [Radiance manual](https://www.radiance-online.org/learning/documentation/manual-pages/pdfs/gendaylit.pdf) for the oracle's irradiance and coordinate conventions.
- [Convergence record](convergence-validation.json): **198 CPU solves / 66 sweeps**, three sites across both hemispheres, two seasons, fixed and both trackers. Largest absolute mean-sunlight differences from each sweep's finest reference: sky **0.0792**, direct timing **0.1013**, grid **0.7125**, pose bin **0.0011 percentage points**.
- [Dense sampling record](sampling-convergence-validation.json): **12 solves**, 384-module winter trackers in both hemispheres, opaque/transmitting modules, 288 receivers and one/four/nine samples per cell. Maximum area-mean difference from nine samples: **0.2217 percentage points**. Sampling convergence is not monotonic in every case and these are not per-cell accuracy bounds.

## External validation still required

The repository now includes Chromium, Firefox, WebKit and mobile-WebKit smoke CI, plus an opt-in hardware WebGPU job. Test discovery succeeds (16 cases, hardware cases conditional), but those new hosted workflows have not run in this local session. Only Chromium was available through the connected browser. The viewport override did not change the effective viewport, so no new mobile-device pass is claimed. The GPU CI job requires an owner-provided runner labeled `aed-webgpu`; it is not silently enabled on an unconfigured runner.

Measured field comparison still requires a dataset with surveyed array geometry, weather, receiver locations and ground irradiance/PPFD. No such dataset was supplied. Independent PAR partition/conversion calibration, the rejected low-sun Radiance sky case, physical mobile/Safari/Firefox checks and upper-limit annual throughput remain documented validation limits. No universal accuracy threshold or broad production-validation claim is introduced.

## Reproduce

Run `npm test`, `npm run build`, `npm run format:check`, `npm run archive:verify` and `npm audit`. Native Radiance is required for `npm run validate:radiance` and `npm run validate:transmission`. For independent physics, create a separate Python environment using `scripts/requirements-validation.txt`, then set `AED_VALIDATION_PYTHON` to its Python executable and run `npm run validate:physics`; this adds no Python runtime requirement to the browser app. Run `npm run validate:convergence`, `npm run validate:sampling` and `npm run validate:performance` for the recorded sensitivity/performance fixtures. The controlled baseline microbenchmark requires commit `e549b7a` in local Git history. Browser CI installs its pinned Playwright engines and runs `npm run test:browser`; local validation pages remain excluded from the production bundle.
